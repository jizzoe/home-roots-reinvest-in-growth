## Defect found in the verification procedure

**The plan's original guardrail command returned `allowed`, not `explicitDeny`.**

The `ProtectOtherProjectInstances` statement denies on the condition
`ec2:ResourceTag/Name` matching `jra-*`. `simulate-principal-policy` does not
resolve a real resource's tags; it evaluates only the context it is given. With
no context entry the condition never matches, the account-wide `ec2:*` allow
governs, and the simulation reports `allowed`.

The policy was never wrong. The test was. Left uncorrected it would have produced
a passing-looking result that proves the absence of the guardrail rather than its
presence — the same shape as the M1 receipt failure and the reference project's
`cold-stop`, where a check reported success while establishing nothing.

The plan was corrected on 2026-09-06 to require `--context-entries`, to require
confirming the tag value rather than assuming it, to add the four tag-independent
denies above, and to add the live-API checks below.

## Assume path

The plan specified `source_profile = joe-rice-admin`. No such profile exists;
that identity arrives through an `aws login` session on the `default` profile,
and `source_profile` requires static credentials. `~/.aws/config` was configured
to route through the existing `terraform` bridging profile instead, matching how
`jra-platform-terraform` is already wired:

```ini
[profile hrf-platform-terraform]
region = us-east-1
source_profile = terraform
role_arn = arn:aws:iam::389633344341:role/hrf-platform-terraform
```

Verified: `aws sts get-caller-identity --profile hrf-platform-terraform` returns
`arn:aws:sts::389633344341:assumed-role/hrf-platform-terraform/botocore-session-...`

The prior file was backed up to `~/.aws/config.bak-20260906230427`. The plan was
corrected to describe this chain and its dependency on the `default` profile
holding a current `joe-rice-admin` session.

`s3:ListAllMyBuckets` is denied under this profile. That is an implicit deny from
the intended `hrf-*` scoping, not a guardrail failure and not a misconfiguration.
