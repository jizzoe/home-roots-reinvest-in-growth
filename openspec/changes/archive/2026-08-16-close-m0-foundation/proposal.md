## Why

M0 delivered its four planned OpenSpec changes and the planning-root setup, but the milestone remains represented as a draft because its acceptance evidence and closure decision were never consolidated. This leaves the roadmap stale and makes it unclear whether M1 can become the active planning milestone.

## What Changes

- Create a durable M0 closure audit that maps every M0 candidate slice and acceptance condition to archived change artifacts, accepted living specifications, or explicit planning-root evidence.
- Reconcile the M0 design brief so its status, repository naming context, candidate-slice history, and next action match the archived foundation work.
- Mark M0 complete in the V1 milestone roadmap, resolve its recorded blocking questions from accepted sources, and name M1 as the next milestone to propose and apply through its separate component-local lifecycle.
- Preserve all existing M1 gates: no component repository creation, external account setup, implementation, cloud work, or participant data use is authorized by M0 closure.

## Capabilities

### New Capabilities

None. This is a documentation and evidence-reconciliation change; it introduces no product behavior.

### Modified Capabilities

None. Accepted requirements in `openspec/specs/` are unchanged.

## Impact

Affected planning artifacts are `ai-planning/design-briefs/m0-sdd-and-product-foundation.md`, `ai-planning/design-briefs/V1 Scope Map and Milestone Plan.md`, and a new M0 closure-audit evidence record. No code, API, executable contract, repository, vendor account, cloud resource, credential, cost commitment, sensitive data, or external system is affected.
